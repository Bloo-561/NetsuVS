## Working on the project
- Project on the user's PC: `E:\Netsu Projects\Netsu Fighter\Godot\netsu-vs` (Godot 4.7.2 mono, Mahou SakugaEngine). Reached through the linked computer. Its shell runs in a Linux VM, with the project at `$HOME/mnt/netsu-vs` (or only `$HOME/mnt/cecilia` when just `actors/cecilia` is connected, as on Oct 23). Blender and Aseprite connectors were available on Oct 21.
- Repo PRIVATE; never use the Mahou EOS credentials; no permission to delete files (move them to `_backup_stage_select/pre_<name>/`; that folder has a `.gdignore`; scene/resource backups as `.tres.bak` / `.tscn.bak`).
- **Writing files to the PC:** the bridge sometimes delivered an OLD copy when a staged path was reused. Stage every push to a fresh unique path (e.g. `/mnt/user-data/outputs/push_00NN/<name>_vN.ext`), then verify on the PC: md5 for text files, pixel samples for PNGs (the bridge re-encodes PNGs, so their md5 changes). Writing directly with the device shell (device_bash) avoids the bridge copy.
- **Godot uid cache:** a stray copy of a resource inside the project can take over its uid (Oct 20 crash). Fix: rename the copy, close Godot, rename `.godot/uid_cache.bin` and `.godot/editor/filesystem_cache10`, reopen Godot so it rescans. The `.old` copies of those two files can be deleted.
- **Blender connector:** keep each call under ~40 s (a single EEVEE frame at `ss=2` is ~17 s); `ss=4` crashed the render. A dropped call can leave the scene changed; re-check before continuing.
- C# changes need a **Build** in Godot. Unconfirmed in game since they were written: the pause-input fix, Overdrive v2, contact-only slash FX.
