The art port chat (Oct 23–24) put the finished drawings in `Fighting_Game_All_Sprites` into the game: Cecilia's new

## Working on the project
- Project on the PC: `E:\Netsu Projects\Netsu Fighter\Godot\netsu-vs` (Godot 4.7.2 mono, Mahou SakugaEngine). Drawings:
  `C:\Users\elvis\Downloads\Fighting_Game_All_Sprites`. Both were connected to the chat (device shell:
  `$HOME/mnt/netsu-vs`, `$HOME/mnt/Fighting_Game_All_Sprites`). The device shell has Python 3 with numpy, OpenCV and
  Pillow, so the tools in `tools/sprite_port/` run there directly; to run them on Windows yourself:
  `pip install numpy opencv-python pillow`.
- Rules (unchanged): repo PRIVATE; never the Mahou EOS credentials; no deleting on the PC (move to
  `_backup_stage_select/pre_<name>/`, `.tres.bak` / `.tscn.bak`); never a copy of a scene/resource elsewhere in the
  project (uid clash); new `[ext_resource]` lines at the top; `.gdignore` on work folders; keep each file's uid;
  C# changes need a **Build**. Bridge writes: a fresh push folder each time and an md5 check on the PC (or write with
  the device shell).
- Don't run git in the device shell: it can't delete its own lock files there (no delete permission) and leaves
  `.git/*.lock` behind. Git is the user's.
- Running Python in the device shell leaves `__pycache__` folders under `tools/`: harmless (Godot ignores them).
